# Security Policy — KOTIKI X LABS

KOTIKI X LABS is a developing voluntary technology initiative. This repository is treated as a project that may be associated with the initiative; this document does not establish a company or legal entity.

## Reporting a vulnerability

Please **do not** publish exploit details, credentials, private data, or a reproducible attack in a public issue or discussion.

1. Open the repository's **Security** tab and use **Report a vulnerability** / private vulnerability reporting if it is enabled.
2. If private reporting is unavailable, contact the repository maintainer through a verified private channel listed on their GitHub profile. Do not guess email addresses.
3. Include the affected file or component, impact, reproduction steps at a safe level, and any suggested mitigation. Remove real tokens, passwords, personal data, and production URLs containing secrets.

We will review reports as capacity allows. Please allow time for acknowledgement and coordinated remediation. Do not access other people's accounts, disrupt services, or test against systems you do not own or have explicit permission to assess.

## Supported versions

Until a project publishes a version-support table, only the current maintained branch is considered for review. No response-time or fix-time guarantee is made.

## Response principles

- Confirm the scope and impact before publishing details.
- Revoke and rotate exposed credentials promptly.
- Prefer a minimal fix and regression check.
- Coordinate public disclosure with the reporter where reasonably possible.

This policy is operational guidance, not a promise that every issue can be detected or fixed.
