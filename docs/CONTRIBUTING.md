# Contributing to KOTIKI X LABS projects

Thanks for wanting to help. Contributions are reviewed for safety, maintainability, licensing, and fit with the project.

## Before contributing

- Check the project's README and open issues first.
- Discuss substantial changes before investing a lot of work.
- Only submit work you created or have permission to contribute.
- Disclose third-party code, assets, fonts, datasets, and dependencies with their source and license.
- Never include credentials, private data, copyrighted material without permission, or code intended to harm users.

## Pull requests

A pull request should include:
- What changed and why
- Relevant screenshots or test evidence, if useful
- How it was tested
- New dependencies and their licenses
- Security/privacy impact, including data collection or new permissions
- Any known limitations or migration steps

Keep changes focused. Do not bundle unrelated redesigns with security fixes. Do not modify deployment settings, secrets, or production services without explicit authorization.

## Review and merge

Submitting a contribution does not guarantee acceptance, publication, employment, partnership, or membership in a legal entity. Unless separately agreed in writing, contributors must not claim to represent KOTIKI X LABS or act on its behalf.

The maintainer may request changes or decline a contribution. No contributor should merge their own change to a protected production branch without the required review. Use a separate branch and preserve a reviewable history.

## Rights and licensing

By submitting a contribution, you confirm that you have the right to submit it. A pull request alone does **not** automatically transfer copyright or grant every possible use. The project's applicable license and any separate written agreement govern permissions. If the project has no clearly stated license, do not assume others have permission to reuse it.

Before work is combined, contributors should agree in writing on any special ownership, licensing, attribution, or compensation terms. Do not rely on this document as a substitute for a signed agreement where one is needed.

## Conduct and safety

Be respectful. Do not publish vulnerability details, private information, threats, harassment, or malicious code. Report security issues using `SECURITY.md`, not a public issue.

These contribution rules are project guidance, not a legal contract or legal advice.
